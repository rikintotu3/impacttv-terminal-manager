# impactTV 端末管理（PWA版）

> **公開URL**: https://impacttv.kaino.co.jp/

[会社ドメイン用のQRコード](qr-code.png)（合言葉は含みません）

## 現在の状態（2026-09-25）

- 会社ドメインと HTTPS の強制を設定済み。スマホでは上記の URL を開いてください。
- **現在はデモモードです。本番の記録は保存されません。** `config.js` の `API_URL` に本番の Google Apps Script の `/exec` URL を設定すると保存先につながります。
- デモは架空の14台です。合言葉は `kaino`。本番の合言葉はスプレッドシート側で別に管理します。

### v2.0.1 の修正

- 接続設定を毎回取得し、保存先を設定しても古いデモ接続が残る問題を修正。
- オフラインでは直近の正常な設定を使用。設定ファイルを読み込めない場合はエラーを表示し、登録を停止。
- 別のアプリのキャッシュを削除しないよう修正。
- 故障済み端末の新規登録でも症状を選択できるよう修正。
- ビルド後も manifest をルートから参照し、ホーム画面のアイコンから正しい開始ページを開くよう修正。

### 公開ファイルの管理

公開用の正本は Git 管理された `_deploy/` です。架空のデモデータだけを配置しています。
ローカルの `app/demo.js` と `app/dist/` は従来の実台帳を使った検証用のため、**そのまま公開しないでください**。
`app/` で修正した場合は、コードだけを確認して `_deploy/` に反映し、公開用 `demo.js` を維持してください。

各端末の黄色シール（バーコード）をスマホで読み取り、状態・設置場所・履歴を記録するアプリの、**PWA（インストール可能なウェブアプリ）版**です。

- どのスマホからでもブラウザで使えます。「ホーム画面に追加」するとアプリのようにワンタップで開けます
- ログインは合言葉方式。**Googleアカウントは不要**です
- 読み取りはスマホの中で行います（読み取りのために写真を送ることはありません）
- カメラにかざすだけの連続読み取りが標準で有効です（使えない環境では自動で撮影方式に）

## 1. しくみ

| 役割 | 置き場所 |
|---|---|
| 画面（この静的アプリ） | 公開用 `_deploy/` を GitHub Pages などの HTTPS ホストに置く |
| 保存先 | 従来どおり Google Apps Script（GAS）＋ スプレッドシート |

サーバー側の `Code.gs` / `Admin.gs` は **v1 からそのまま流用** します（変更・再貼り付けは不要です）。
通信はアプリから GAS のウェブアプリ URL に直接 POST されます。

フォルダ構成：

| ファイル | 役割 |
|---|---|
| `index.html` | アプリ本体（画面・読み取り・通信のすべて） |
| `config.js` | 接続先の設定。**配布時にここだけ編集します** |
| `manifest.webmanifest` / `sw.js` | PWA 用（インストール・オフラインキャッシュ） |
| `demo.js` | デモモード（config.js が空のときに自動で起動） |
| `icons/` | アプリアイコン |

## 2. 導入手順

### (a) GAS 側の準備（すでに運用中なら読み飛ばして OK）

1. スプレッドシートを作り、「拡張機能」→「Apps Script」に `Code.gs`・`Admin.gs`・HTML `index` を貼り付けます
2. スプレッドシートを再読み込みし、メニュー「impactTV管理」→「初期設定（シート作成・更新）」を実行します（初回は承認が必要。完了メッセージに合言葉が表示されます）
3. メニューから既存台帳を取り込みます
4. 右上「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」で、**次のユーザーとして実行：自分／アクセスできるユーザー：全員** にしてデプロイし、表示された URL（`https://script.google.com/macros/s/…/exec`）をコピーします

### (b) アプリを HTTPS ホストに置く

置くのは次の 6 点です（`node_modules` や `package.json` など開発用のファイルは不要です）。

```
index.html / config.js / demo.js / sw.js / manifest.webmanifest / icons/
```

1. GitHub でリポジトリを作り、上のファイルをアップロードします
2. Settings → Pages で公開します（`https://（アカウント名）.github.io/（リポジトリ名）/` のような URL になります）

`npm run build` はローカル検証用です。公開時は、架空データだけを含む `_deploy/` を使用してください。
GitHub Pages 以外の HTTPS ホスト（社内サーバー・Netlify など）でも構いません。**HTTPS 必須**です（カメラと Service Worker が HTTP では動きません）。

### (c) `config.js` に接続先を貼る

`config.js` を開き、(a) の exec URL を貼り付けます。

```js
window.ITV_CONFIG = {
  API_URL: 'https://script.google.com/macros/s/…/exec',
};
```

> 空のままだと **デモモード** で起動します（合言葉 `kaino`。記録は保存されず、再読み込みで元に戻ります）。配布前の動作確認に使えます。

設定変更後はスマホでオンラインの状態でアプリを開き直します。v2.0.1 以降は `config.js` を毎回取得するため、接続先だけの変更では Service Worker の版更新は不要です。画面・アイコン等を変えた場合は `sw.js` の `VERSION` も更新してください。
本番切り替え後は、別々のスマホで同じ台帳が見えることと、登録・再読み込み後も記録が残ることを確認してください。

### (d) スマホで使う

1. スマホのブラウザ（Safari／Chrome）で (b) の URL を開きます
2. 合言葉とお名前を入力して「はじめる」
3. **ホーム画面に追加** すると、次からアプリのようにワンタップで開けます
   - Android／Chrome：設定画面の「ホーム画面に追加（インストール）」ボタン、またはブラウザのメニューから
   - iPhone／Safari：共有ボタン →「ホーム画面に追加」（設定画面にも案内が出ます）
- 「設定」シートの「アプリURL」をこのページの URL にしておくと、GAS メニューの「配布用URL・QRコードを表示」で各店に配る QR コード（`#key=` つき）が作れます

## 3. ローカルでの確認

```bash
npm install
npm run dev
```

表示された URL（例：`http://localhost:5173/`）をブラウザで開きます。
`config.js` が空ならデモモードで起動します（合言葉 `kaino`）。実機のスマホからは `npm run dev -- --host` で同じ Wi-Fi 内の端末から開けます。

本番相当のファイルは `npm run build` で `dist/` に出力されます。

## 4. v1 → v2 の変更点

| 項目 | v1（GAS ページ） | v2（この PWA 版） |
|---|---|---|
| 動作場所 | GAS のウェブアプリ URL | 任意の HTTPS ホスト（GitHub Pages など） |
| インストール | なし | PWA 対応（manifest＋Service Worker・オフラインキャッシュ） |
| かざすだけ読み取り | GAS の仕様変更で無効 | **標準で有効**（設定で撮影方式に切替可） |
| デザイン | 紺色ベース | 刷新（ネイビー×黄色アクセント・角丸カード・画面フェード） |
| ナビゲーション | 戻るボタンのみ | ボトムナビ（ホーム／一覧／設定＋中央スキャン） |
| デモモード | 別ファイル（お試し版.html） | 内蔵（config.js が空なら自動起動・合言葉 `kaino`） |
| 設定の置き場所 | index.html 先頭の CONFIG | `config.js`（分離） |

API プロトコル（`{action, payload, token, user, device, v}` の POST）は従来どおりです。GAS ページ（HTML `index`）も従来どおり使えます。

## 5. 困ったとき

| 症状 | 対処 |
|---|---|
| 「接続先が設定されていません」と出る | `config.js` の `API_URL` が空、または `demo.js` が見つかっていません |
| カメラが開かない | HTTPS で開いているか確認。LINE／LINE WORKS 内なら「ブラウザで開く」。許可を拒否した場合はブラウザの設定からカメラを許可 |
| 「ホーム画面に追加」が出ない（iPhone） | Safari の共有ボタン →「ホーム画面に追加」 |
| 古い画面のまま | 一度閉じて開き直す（Service Worker が新しい版を取得しています）。設定画面のバージョン表記を確認 |
| バーコードが読めない | シール全体を大きく、明るい場所で。だめなら「番号を入力」（下4桁で検索可） |
| 読み取り機能を読み込めない | ネットワークで jsDelivr（fastly.jsdelivr.net）が遮断されていないか確認。一度読み込めていればキャッシュで動きます |
| 「合言葉の確認が必要です」 | 合言葉が変わった可能性。本部に確認 |

そのほかの運用・シート構成・重複防止の仕組みは、従来の『導入手順と仕様メモ』を参照してください。
